# Onyx Scribe — full audit, 2026-08-21

Follow-up to `docs/AUDIT.md` (2026-07-10). That pass reviewed the code ahead of the
selection-transform feature; this one reviews the **whole app as a product about to be
sold**, six weeks and four feature commits later (drafting, style memory, translation,
streaming injection, tone routing, GTM scaffolding).

Baseline verified on this machine:

| Check | Result |
|---|---|
| `swift build` | ✅ clean, 46 s, 5 warning classes (below) |
| `swift run FlowCloneChecks` | ✅ **181 passed, 0 failed** |
| Test surface | 21 suites — **all in `FlowCloneCore` (pure logic)**; the app target has none |
| Uncommitted | 16 modified sources, 6 new source files, 8 new docs — **none committed** |

The engineering quality of what exists is high: `EngineRouter`, `GestureRecognizer`,
`StreamChunker`, `PinnedCapTrimmer` are exactly the right shape — pure, framework-free,
exhaustively tested, with the *reason* for each rule written down. The problems below are
concentrated in three places: (1) the mutable orchestration layer, (2) the parts that were
never given a test seam, and (3) everything a *stranger's* install needs that the author's
install never did.

---

## 1. Correctness findings

Ranked by expected user harm.

### 1.1 HIGH — `VocabularyCorrector` corrupts real words (verified)

`FlowCloneCore/VocabularyCorrector.swift:782` applies each `wrong => right` rule with a
raw, case-insensitive `replacingOccurrences` — **substring match, no word boundary**.
Reproduced locally with rules `ai => AI`, `ok => OK`, `ken => Ken`:

```
in:  "I said the token is broken and it's ok"
out: "I sAId the tOKen is brOKen and it's OK"
```

This is the *same bug class* the July audit fixed in `TextCleanup.stripFillers` — the
sibling function in the same file was missed. It is worse than the original, because:

- it runs on **every dictation, every tier, every language**, before the LLM ever sees the
  text (`DictationController.swift:557`), so even the free/verbatim path is affected;
- the rules are **user-authored**, so short rules (`ai`, `ok`, `ml`, `ui`) are natural to
  write and silently poison everything downstream;
- corrupted text also feeds `HistoryStore`, which feeds `LearnedStore.refresh()` — a wrong
  spelling gets *learned* and re-injected into the cleanup prompt.

**Fix:** tokenize and match on word boundaries (mirroring the `stripFillers` fix), and
preserve the target's casing rather than the rule's. Add regression tests alongside the
existing `TextCleanup word boundaries` suite.

**Also:** `apply(_:)` re-reads `~/.flowclone/vocabulary.txt` from disk on every utterance,
on the hot path. Cache it with an mtime check.

### 1.2 HIGH — `DictationController` shared-state races (still open from July)

Carried over from the July backlog, now confirmed by the compiler:

```
DictationController.swift:525:44: warning: capture of 'self' with non-Sendable type
  'DictationController' in a '@Sendable' closure
DictationController.swift:857:44: (same)
```

`generation`, `lastInjected`, `lastInjectedApp`, `frontApp`, `frontBundleID`,
`insertionContext`, `partialLang` are written from main-thread hotkey handlers and read/
written from the detached pipeline `Task` with no synchronisation. The `generation` counter
is the cancel mechanism for the *entire* pipeline — a torn read there means an Esc-cancelled
dictation can still paste.

Rare in practice (needs a mid-dictation cancel or engine switch), but this is also a **hard
blocker for Swift 6**: the same file produces `reference to captured var 'self' in
concurrently-executing code; this is an error in the Swift 6 language mode` in
`OnboardingView.swift` (4×) and `FoundationModelCleanup.swift:200/203` (`NSLock.lock`/
`unlock` unavailable from async contexts).

**Fix:** `@MainActor`-confine `DictationController`, hopping off only for the `await` calls
into ASR/LLM. It's a mechanical refactor of one file and it closes the whole warning class.

### 1.3 MEDIUM — `TextInjector.commitStream` blocks the main thread

`TextInjector.swift:99–102` enforces the F3 settle gap with
`Thread.sleep(forTimeInterval: gap)` — and `commitStream` is called exclusively inside
`await MainActor.run { … }` (`DictationController.swift:442, 467, 482`). So with streaming
injection enabled, the main thread stalls up to **110 ms per commit**, freezing the pill's
waveform and every other UI surface at exactly the moment the user is watching it.

**Fix:** move the wait out of the MainActor hop — `try await Task.sleep` in
`runStreamingCleanup` *before* calling `commitStream`, keeping the paste itself atomic on
main.

### 1.4 MEDIUM — Clipboard restore is still a fixed 0.5 s timer (open from July)

`TextInjector.inject` and `endStream` restore the user's clipboard on a hardcoded 0.5 s
delay. A slow target app can process the Cmd+V *after* the restore, pasting the user's
previous clipboard instead of their dictation. Low incidence, high annoyance, and it now
has two call sites instead of one.

**Fix:** poll `NSPasteboard.general.changeCount` and restore once the paste is observed
(with a timeout backstop). Longer term, prefer the AX write path that `SelectionEditor`
already implements — it never touches the clipboard at all.

### 1.5 MEDIUM — Whisper + auto-language still mis-decodes (open from July)

`ASREngine`'s default `transcribeAuto` returns `confidence = 1.0` and decodes with the
*pinned* language. `EngineRouter`'s `detectionReliable` rule correctly stops that
mislabelled `"en"` from reaching Apple FM — but the **transcript itself is already wrong**:
a Whisper user with auto-language on, speaking Bulgarian, gets a Latin-script decode that
no downstream routing can rescue.

**Fix (pick one):** implement real detection via WhisperKit's language-detection API, or
disable the auto-language toggle in Settings while Whisper is the selected engine and say
why. The second is a 10-line honest fix.

### 1.6 LOW — assorted

| Location | Issue |
|---|---|
| `HubView.swift:417` | `data.first!` on the Insights chart — force unwrap; confirm the producer can never return an empty series |
| `PillController.swift:247` | `NSScreen.screens.first!` — crashes on a headless/no-display session |
| `Stores.swift:161` | Streak uses `Date().addingTimeInterval(-86_400)`; DST transitions make a "day" 23 or 25 h, so streaks can double-count or break. Use `Calendar.date(byAdding: .day, value: -1, …)` |
| `Licensing.swift:482` | `TrialClock.effectiveNow = max(now, lastSeen)` is monotonic with no ceiling — one forward clock excursion (dead PRAM battery, a VM snapshot) permanently burns trial days with no recovery path. Cap the forward jump, or ignore jumps > ~30 days |
| `CleanupPrompt.situational` | The destination app name and the user's per-app profile string are interpolated into the system prompt without `PromptSanitizer` — low risk (both semi-trusted) but inconsistent with the rest of the file |
| 6 deprecations | `GenerationOptions(sampling:)` → `samplingMode:` (7×), `CGWindowListCreateImage` → ScreenCaptureKit (3×) |

## 2. Shipping and operability gaps

These are what actually stand between "works on my Mac" and "a stranger paid for it."

### 2.1 There is no diagnostics channel at all

Zero `os_log` / `Logger` anywhere in the codebase. All ~110 diagnostics are `print()` to
stdout — which, for a `.app` launched from Finder, **goes nowhere**. When a customer writes
"it stopped transcribing," there is currently no way to find out why. (You hit exactly this
yourself on 2026-07-26 with the "didn't catch that" mic issue, and it was never root-caused.)

**Fix:** swap `print` for `Logger(subsystem: "com.todor.flowclone", category: …)` so output
lands in the unified log and is captured by `sysdiagnose`; add a **Copy diagnostics** menu
item that dumps permissions, engine availability, model versions, entitlement state and the
last N error lines — **metadata only, never dictated text**. That last constraint is itself
a selling point; make it visible in the dump header.

### 2.2 No crash reporting, no feedback path

On the GTM pre-launch checklist, unbuilt. For a non-App-Store, non-telemetry product you
need at minimum a mailto/form in the Hub, ideally with the diagnostics dump pre-attached
and shown to the user before sending.

### 2.3 No CI

No `.github/`. `FlowCloneChecks` is excellent and free to run; nothing runs it. A macOS
GitHub Action doing `swift build && swift run FlowCloneChecks` is ~15 lines and is the
cheapest insurance a solo shipper can buy.

### 2.4 Nothing is committed

`git status` shows 16 modified sources and **6 new source files** — `SelectionEditor`,
`EngineRouter`, `GestureRecognizer`, `PromptSanitizer`, `SelectionCommand`, `StreamChunker`
— untracked. That is the entire transform feature, the latency fix and the streaming work
sitting outside version control. One `rm -rf` or bad `git checkout` away from gone.

Related: `graphify-out/` is **checked in** and dominates every diff (27,446 lines in
`graph.json` alone). It's a derived artifact; add it to `.gitignore`.

### 2.5 Release mechanics are scaffolding only

`CFBundleShortVersionString` is `0.1.0`, `CFBundleVersion` is `1`, `web/appcast.xml` is a
commented-out template, Sparkle is inert until a Developer ID exists. That's fine as a
*state*, but note the ordering trap: **the first shipped build must already contain a
working Sparkle updater and a sane version number**, or your earliest customers can never
be updated. Get 2.5 right before the first paid download, not after.

### 2.6 The riskiest code has no automated coverage

All 181 assertions live in `FlowCloneCore`. The app target — `DictationController`'s
orchestration, `TextInjector`, `SelectionEditor`, `ContextReader`, the stores — has none.
`docs/SMOKE-TEST.md` is a genuinely good manual gate, but it's ~50 checkboxes that must be
re-run by a human after every change, which means in practice it won't be.

**Fix:** extract protocols for the two AX/paste boundaries (`Injecting`, `SelectionReading`)
and move the orchestration decisions — *which* engine, *whether* to inject, *what*
`lastInjected` becomes, *when* to degrade — into a pure, testable reducer, the same way
`GestureRecognizer` was extracted from the hotkey handling. That pattern already worked
twice in this codebase; the pipeline is the third and biggest candidate.

## 3. Product and UX gaps

### 3.1 The accessibility promise isn't kept

`PRODUCT.md` commits to "VoiceOver-first… every control, state, and the pill's status
changes carry meaningful labels/announcements; the Hub is fully navigable."

Actual state: **`OnboardingView.swift` is the only file with accessibility modifiers** (4 of
them). `HubView.swift` (959 lines), `PillView.swift`, `DictionarySettingsViews.swift` and
the Settings surfaces have **zero**. The pill — the signature always-on element — never
announces a state change.

Reduce Motion, by contrast, is done properly and consistently (`MotionPreferences`,
branched in 12 places). So this is a gap, not a philosophy problem.

Worth fixing on merit, but also on market: **dictation users and accessibility users are
the same population.** A VoiceOver-clean local dictation app is a category of one, and it's
a far cheaper wedge than competing on latency.

### 3.2 "Zero install" and "tones" are mutually exclusive, and the user finds out late

Confirmed by your own 2026-07-26 fix: Apple FM ignores restyle instructions, so
`EngineRouter` rule 4 forces every non-Faithful tone to Ollama. But Apple FM is the
zero-install default. A new user who picks "Super Casual" gets a pill nudge *after* their
dictation fails to be styled.

**Fix:** make the dependency legible at choice time — tone cards that need the optional
model should say so, with the install command one click away. Right now the honesty arrives
one dictation too late.

### 3.3 Finding 1.1 hits the free tier hardest

The free tier's whole value proposition is "clean verbatim." It skips the LLM but still
runs `VocabularyCorrector` — so a free user with a two-letter dictionary rule gets
*corrupted* verbatim, which is worse than raw. Fix 1.1 before any free tier ships.

## 4. Innovations worth integrating

Ranked by differentiation ÷ effort. The first three are latency; the rest are moat.

### 4.1 Stream the Ollama path too — ~1 day, highest value

You built streaming injection (`StreamChunker`, `runStreamingCleanup`, F1–F14 guards) and
then scoped it to the **primary Apple FM path only**. But `EngineRouter` sends *all
Bulgarian* and *every restyle tone* to Ollama — which runs `stream: false` and makes the
user wait for the entire generation. The perceived-latency win you paid for in complexity
applies to precisely the paths that don't get it.

Ollama's `/api/chat` supports `stream: true` with NDJSON deltas. `StreamChunker` is
engine-agnostic and already unit-tested; `runStreamingCleanup`'s state machine doesn't care
which engine feeds `onPartial`. This is mostly plumbing an `AsyncSequence` into
`OllamaClient` and deleting the `engine == .apple` condition at
`DictationController.swift:674`.

### 4.2 Speculative cleanup on pause — the biggest *actual* latency win available

You already re-transcribe the buffer roughly once a second during recording
(`runPartial`). Extend it: when the level meter shows ~400 ms of silence mid-utterance,
fire a cleanup pass on the partial transcript *while the user is still holding the key*.
On release, if the final transcript matches the speculated input, the answer is already in
hand — near-zero perceived cleanup latency. If it diverges, throw it away and run normally.

This is only viable because the models are local: speculating costs you idle ANE cycles, not
API spend. A cloud competitor structurally cannot do it. `generation` already exists as the
cancellation token, and `FMSessionPool` already handles warm-session churn.

### 4.3 Phonetic vocabulary correction — makes style memory actually compound

Today the personal dictionary is (a) a literal string replace and (b) a prompt section.
Neither fixes the dominant real error: the ASR hears a *phonetically close* variant of a
name it has never seen — Katya / Katia / Catia / Kate-ya.

Index the user's vocabulary + `LearnedStore` terms by a phonetic key (Metaphone, or
`NLTagger`-assisted), then correct ASR tokens whose phonetic key matches a known term but
whose spelling doesn't. Deterministic, no LLM, sub-millisecond, and it turns `StyleMemory`
from a prompt hint into a system that measurably improves with use. Also fixes 1.1 as a
side effect, since phonetic matching is inherently token-scoped.

### 4.4 Local retrieval for drafting — the strongest moat extension

Context-aware drafting reads the on-screen thread via AX and writes the reply locally. The
natural next step is the one no cloud tool can follow: **draft grounded in the user's own
documents.** A small `NLEmbedding`-based index over the Scratchpad, pinned history, and one
user-chosen folder; at draft time, retrieve the 3–5 most relevant passages and add them to
the context alongside the screen content.

"It writes the reply *and it knows what you already told this client last month* — and
none of it left the Mac" is a materially stronger pitch than anything in the current
feature list, and it reuses the drafting pipeline wholesale.

### 4.5 Replace `replaceLast`'s blind backspaces with AX-located edits

`TextInjector.replaceLast` posts N backspace events and hopes the caret is where it was;
`SelectionEditor.caretIsAtEndOf` is a guard bolted on top of a fundamentally unsafe
primitive (it was ship-blocker #3 in the July audit). Meanwhile `SelectionEditor` already
does verified, fingerprinted, in-place AX replacement properly.

Merge them: locate the target span by searching the focused element's AX value for
`lastInjected`, then replace that range. That both removes the last data-loss primitive in
the app **and** unlocks a better feature — "change Thursday to Friday" targeting arbitrary
earlier text, not just the most recent paste.

### 4.6 Learn per-app profiles instead of only storing them

`profiles.json` exists and is editable, but nothing populates it. After N dictations into an
app, offer a profile: *"You dictate into Slack ~40× a week — want Slack to default to Super
Casual?"* All the data is already in `HistoryStore` (`app`, `tone`, `raw` vs `text`), all of
it local. Cheap to build, reads as genuine intelligence.

### 4.7 Commit-on-pause mode for long-form dictation

Push-to-talk is the only gesture, which caps a session at however long someone will hold a
key. Add a mode where a ~1.2 s silence commits the sentence and recording continues. The
partial loop and `StreamChunker`'s boundary detection are most of the machinery already;
this is largely a mode flag plus a silence detector on `onLevel`.

### 4.8 Turn `EngineRouter` into a capability table

The router is the cleanest thing in the codebase, but it hardcodes two engines and encodes
capability as prose in rule comments ("Apple FM IGNORES the restyle instruction"). Promote
that to data: each engine declares `{ languages, canRestyle, latencyClass, available }` and
the router picks by requirement. Adding a third engine — an MLX-hosted model, or Apple FM
once it learns to restyle — becomes a table row rather than a rewrite, and per-utterance
routing (short → Apple, long/toned → Ollama) becomes expressible instead of ad hoc.

### 4.9 Prove the privacy claim instead of asserting it

The entire pitch is "it physically cannot leak," and the app currently supports that with
prose. Ship a **Privacy pane that demonstrates it**: live outbound-connection count for the
process (should be `localhost:11434` and nothing else), bytes sent since launch, and a
plain-language "no network activity since launch — 6 d 4 h."

Nobody in this category does this. It converts the differentiator from a marketing claim
into a screenshot, which is exactly the artifact that travels on Hacker News and r/macapps —
the two channels your GTM plan leads with.

## 5. Suggested order

**Before anything else (hours):** commit the working tree; `.gitignore` `graphify-out/`.

**Ship-blockers (days):** 1.1 vocabulary corruption → 2.1 logging + diagnostics dump →
1.2 MainActor confinement (also clears Swift 6) → 1.3 main-thread stall → 2.3 CI.

**Before the first paid download:** 1.4 clipboard race, 1.5 Whisper honesty, 2.2 feedback
path, 2.5 version + Sparkle, 3.1 accessibility pass on `HubView`/`PillView`, 3.2 tone/engine
legibility.

**Then, in order of payoff:** 4.1 Ollama streaming → 4.2 speculative cleanup → 4.3 phonetic
vocabulary → 4.9 privacy pane (cheap, and it's the launch asset) → 4.5 AX-located edits →
4.4 local retrieval.

`docs/SMOKE-TEST.md` should be re-run in full after 1.2, 1.3 and 1.4 — they all touch the
injection path, which has no automated coverage.
